# Demo build

A self-contained build of beatbox for the portfolio, running with **no
backend**. A visitor lands signed in as a producer (`@sila`) and can browse,
play, buy, and upload beats against in-memory sample data. Nothing persists —
a refresh restores the seeded world.

This lets the app be shown live while the real (Supabase-backed) product is
still under development.

## Run it locally

```bash
npm run dev:demo        # dev server in demo mode
# or
npm run build:demo      # production demo build → dist/
npm run preview         # serve the built demo
```

`npm run dev` / `npm run build` stay on the **real** backend and are
unaffected.

## How it works

Demo mode is one flag, `VITE_DEMO=true`, set by `.env.demo` (loaded via Vite's
`--mode demo`). When on:

- `src/supabase-client.js` reports `isConfigured` true but leaves the real
  Supabase client `null`.
- `src/main.js` takes the demo branch and calls `src/demo/demo-boot.js`
  instead of the normal `initReal()`.
- `demo-boot.js` seeds `window.beatBank` from the sample catalog and builds
  the `window.beatboxApi` bridge (the same surface the classic UI scripts
  call) pointed at an in-memory store, `src/demo/demo-store.js`.

Because the existing UI (`carousel.js`, `list-view.js`, `transport.js`, the
auth bar) talks through `window.beatBank` and `window.beatboxApi`, none of it
changes — it renders the demo data unchanged.

### The demo layer (`src/demo/`)

| File | Role |
|------|------|
| `demo-data.js` | The seeded world: producer session, 8 beats, purchases, one pending trade offer. Shapes match the real repos exactly. |
| `demo-store.js` | In-memory backend — same function names as the repos, mutating cloned state. |
| `demo-boot.js` | Entry path: seeds globals, builds the API bridge, mounts chrome. |
| `demo-checkout.js` | Mock "producer's checkout" shown instead of a real Gumroad redirect. |
| `demo-chrome.js` | DEMO badge, signed-in bar, intro notice, library panel, offers inbox. |
| `demo.css` | Styling for the above, reusing the app's `--accent` etc. |

### Sample audio

The demo ships four synthesized loops (`asset/sound/demo/loop-0{1..4}.wav`),
generated by `scripts/gen-demo-audio.mjs` — no third-party audio, no
licensing. Waveform peaks were extracted with `scripts/gen-demo-peaks.mjs` and
baked into `demo-data.js` so the transport draws accurate waveforms.

To regenerate:

```bash
node scripts/gen-demo-audio.mjs
node scripts/gen-demo-peaks.mjs   # prints peaks to paste into demo-data.js
```

## What's real vs. roadmap in the demo

- **Real, interactive:** browse, play, seek, waveform, expand a row for
  licences, buy (mock checkout → unlocks + lands in library), claim a free
  beat, upload a beat (appears in the catalog, plays back).
- **Preview of where it's headed:** the **offers inbox** and **library** open
  as panels off the sidebar; messaging is noted as in development. The trade
  *settlement* logic underneath is already built server-side — only its UI is
  a preview here.

## Deploy (Vercel)

`vercel.json` already sets the demo build:

- **Build command:** `npm run build:demo`
- **Output directory:** `dist`

Import the repo in Vercel and deploy — no environment variables are needed
(the demo has no secrets). If configuring by hand instead of via
`vercel.json`, set those two fields and add the two cross-origin-isolation
headers from `vercel.json`.

Netlify equivalent: build command `npm run build:demo`, publish directory
`dist`.
